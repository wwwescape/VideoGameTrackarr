- 2026-08-22 10:42 — Fixed the About page's manual "Check for updates" button not actually re-checking GitHub for a genuinely new release. Root cause: `GET /api/version` (`backend/app/api/routes/version.py`) → `version_service.get_latest_release()` caches the raw GitHub API response for 6 hours (`version_service.py`'s `_CACHE_TTL_SECONDS`), and the frontend button's `refetch()` only bypassed the *frontend's* 1-hour `staleTime` (`useVersion.ts`) — it never reached past the backend's own cache, so a manual click could silently replay a stale answer for up to 6 hours after a real release went out. `get_latest_release` gained a `force: bool` param that skips the cache *read* for that one call (still writes the fresh result back to cache afterward, refreshing the window — not a cache-disabling flag, just a one-off bypass), threaded through a new `GET /api/version?force=true` query param. `useVersion.ts` now exposes `checkForUpdates()` instead of raw `refetch()` — uses a `forceRef` so the next `queryFn` invocation asks for `force=true` without changing the hook's `queryKey`/`queryFn` identity on every render (plain `refetch()` re-runs the same closure, so there was no way to vary the call's arguments per-invocation without this). `About.tsx`'s button now calls `checkForUpdates()`. New backend tests confirm force bypasses the cache for that call while still refreshing it for later non-forced calls, and that the route's `force` query param propagates through. Verified via `pytest` (17 version-related tests pass) and `tsc --noEmit` (clean); live backend confirmed serving the new `force` param via `/openapi.json`.
